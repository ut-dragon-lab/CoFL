# CoFL-S evaluation on RxR-1600

[RxR-1600](../benchmarks/rxr_1600/README.md) is the fixed selected subset used
for this navigation task. Its data provider is
[`benchmarks/rxr_1600/dataset.json`](../benchmarks/rxr_1600/dataset.json).
Model evaluation uses
[`cofl_s_rxr_online.yaml`](../configs/evaluation/cofl_s_rxr_online.yaml) and
[`rxr_1600.yaml`](../configs/evaluation/rxr_1600.yaml).

## Reference scores and scope

| Selected subset | Episodes | NE (m) | OS | SR | SPL |
| --- | ---: | ---: | ---: | ---: | ---: |
| RxR-1600 | 1,600 | 7.0918005495 | 0.504375 | 0.351875 | 0.2722291819 |

These descriptive reference values aggregate recorded per-episode outputs for
the selected IDs. They are not independent validation or official full-split
results. A fresh complete 1,600-episode rollout has not been performed for this
release, and the values are not a guarantee for a new evaluation. Report the
subset ID, checkpoint and execution protocol when comparing results.

The subset spans 11 scenes. Sub-instruction lengths vary; the dataset does not
promise that every chunk fits a 64-token model input. The reference tokenizer
budget contains one EOS and at most 63 content tokens. Apply the same model
input settings when reproducing the evaluation.

## Evaluation contract

Prepare the dataset, configure local assets, and run from the CoFL root:

```bash
uv run --locked python -m cofl.online --config configs/evaluation/cofl_s_rxr_online.yaml
```

The reference CoFL-S checkpoint SHA-256 is
`015acb99eaf3fa8a47833e2c6cc6166eb6d18b274344789c7ed850a12763ca42`.
The sanitized release copy has SHA-256
`cce748914a88167a2566ffd724ed43f0f651841dcab25afcbef706f5ccd62b12`.
Its tensors and processor assets are unchanged. Historical results retain the
original hash; use a new result directory for the release copy.
Weights, Matterport3D scenes and the Habitat environment must be supplied
separately. The supplied YAML exposes all execution and controller settings.
The data manifest is independent of these assets and never stores their results.

The evaluated protocol uses strict Landmark oracle sub-instructions, reference
edge progress with lookahead 6, a 100 Hz kinematic plant, a 50 Hz controller,
30 Hz sensor schedule and 5 Hz planning. Model trajectories are converted to
world coordinates and tracked with velocity commands. Simulation advances
synchronously with inference; these rates refer to simulated time. This is
continuous pose/velocity navigation with ground-truth instruction progress.

Core metrics use protocol `cofl-s-vln-benchmark-v6` and
`vlnce_official_core_v1`: NE is terminal navmesh geodesic distance, OS records
reaching within the strict 3 m threshold anywhere on the executed plant path,
and SR additionally requires an explicit stop. A timeout alone is not success.
The input paths and output directory change for the release; checkpoint,
controller, sensors, metric semantics and 16-worker/16-batch execution settings
are preserved from the source run.

Exact prepared data identities are reproducible from the manifest and source
files. Dynamic batch composition and numerical execution may vary between
runs, so frozen inputs and matching configuration do not guarantee bitwise
identical rollout metrics. Report any new evaluation as a new run.
